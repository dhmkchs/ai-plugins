description: REST/GraphQL API 계약을 스키마·에러·인증·페이지네이션까지 계약 우선으로 설계한다
argument-hint: [엔드포인트/리소스, 예: "POST /users 회원가입"]
---

`api` 스킬을 사용해 진행한다. 스킬의 절차를 건너뛰지 말고 순서대로 따른다.

사용자가 전달한 내용:
$ARGUMENTS

구현 전에 계약(요청/응답 스키마·상태코드·에러 shape)을 먼저 못 박는다.
인가는 프론트가 아니라 서버에서 리소스 접근마다 검증하도록 설계한다.
비어 있으면 어떤 리소스·동작을 설계할지, 인증/권한 요구가 무엇인지 먼저 묻는다.
