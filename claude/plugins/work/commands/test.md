`test` 스킬을 사용해 진행한다. 스킬의 절차를 건너뛰지 말고 순서대로 따른다.

사용자가 전달한 내용:
$ARGUMENTS

먼저 프로젝트의 테스트 관례(러너·단정 스타일·파일 위치·픽스처)를 읽고, 그 위에 표준을 얹는다.
**새 테스트 프레임워크를 도입하지 않는다.**
행위 표를 먼저 적고(정상 → 경계 → 에러 → 상태 전이), 테스트를 쓴 뒤 **실제로 돌려** 통과를 확인한다.
버그 재현이면 수정 전에 실패를 한 번 본다.
브라우저 회귀 테스트는 `e2e`, 화면 일회성 검수는 `browser`를 안내한다.
비어 있으면 어떤 단위를 덮을지 먼저 묻는다.
