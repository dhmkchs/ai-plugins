# ADR 템플릿

`docs/adr/NNNN-kebab-title.md`에 아래를 채운다. 섹션 제목은 유지하고, 해당 없는 항목만 "없음"으로 남긴다.

```markdown
# ADR-NNNN: <결정을 한 줄로>

- 상태: Proposed | Accepted | Superseded by ADR-MMMM | Deprecated
- 날짜: YYYY-MM-DD
- 결정자: <사람/팀>
- 관련: <티켓 / PR / 상위 ADR>

## 컨텍스트

어떤 문제·요구가 이 결정을 강제하나. 제약(성능·마감·팀·기존 스택·규정)을
검증 가능한 사실로 적는다. "원한다"가 아니라 "p99 200ms를 넘으면 안 된다".

## 고려한 대안

### 대안 A — <이름>
- 장점: ...
- 단점: ...

### 대안 B — <이름>
- 장점: ...
- 단점: ...

(현상 유지 / 아무것도 안 하기도 유효한 대안이면 함께 적는다)

## 결정

**채택: 대안 X**

근거: 이 맥락의 어떤 제약이 이 안을 골랐나. §컨텍스트의 제약과 직접 연결한다.
왜 이게 일반 원칙이 아니라 "이 맥락에서" 맞는지 한 줄 덧붙인다.

## 결과

- 긍정: 이 결정이 열어주는 것
- 비용/부채: 포기한 것, 나중에 물어야 할 빚
- 후속: 이 결정이 강제하는 다음 작업 (없으면 "없음")

## 검증

이 결정이 옳았는지 나중에 무엇으로 판단하나 (지표·조건). 선택 사항.
```

## 최소 버전 (경량 ADR)

가벼운 결정엔 아래 5줄로 충분하다. 대안·결과만은 빼지 않는다.

```markdown
# ADR-NNNN: <결정>
- 상태: Accepted · 날짜: YYYY-MM-DD
- 맥락: <왜 정해야 했나 한 줄>
- 대안: A(...) vs B(...) — B 채택, 이유 <한 줄>
- 결과: <감수하는 비용 한 줄>
```
