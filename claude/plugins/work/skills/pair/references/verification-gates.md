# 검증 게이트

AI 출력은 아래 게이트를 **순서대로** 통과해야 코드베이스에 들어간다.
하나라도 실패하면 다음 게이트로 넘어가지 않고 그 자리에서 고친다.

## Gate 0 — 존재 검증 (환각 탐지)

AI가 쓴 API·함수·옵션이 실제로 존재하는가. 30초 안에 끝난다.

- import한 패키지가 `package.json` / `pom.xml` / `build.gradle`에 있는가
- 호출한 메서드가 그 타입에 실제로 있는가 (타입 체커·IDE·`javap`·`node -e`)
- 옵션 이름이 오타 없이 맞는가 (조용히 무시되는 옵션이 최악이다)
- 버전 차이가 있는 API인가 (Java 8 vs 17, Node 16 vs 22)

**빠른 확인**
```bash
# TypeScript: 타입 오류만 빠르게
npx tsc --noEmit

# Java: 컴파일만
javac -d /tmp/out $(git ls-files '*.java') 2>&1 | head -20

# 패키지가 실제로 설치돼 있는지
node -e "require.resolve('lodash')" ; ./gradlew dependencies --configuration compileClasspath | grep -i <lib>
```

환각 신호: 지나치게 편리한 이름의 메서드(`array.sumBy`, `List.firstOrNull` in Java), 존재하지 않는 유틸 패키지, 최신 기능처럼 소개되는 문법.

## Gate 1 — 계약 검증

- 함수 시그니처가 내가 정한 것과 동일한가 (파라미터 순서·타입·반환)
- null / undefined / Optional 처리 정책이 기존 코드와 일치하는가
- 예외를 던지는가 값을 반환하는가 — 호출부 기대와 맞는가
- 부수효과가 새로 생겼는가 (전역 변수, 인자 mutation, 로깅, I/O)

인자를 직접 변경하는(mutate) 코드는 AI가 자주 만든다. 호출부가 이를 기대하지 않으면 조용한 버그가 된다.

## Gate 2 — 정확성 검증

**Dry run**: 예제 입력 1개를 손으로 추적하며 각 반복의 변수 상태를 적는다. 3줄 이상 추적이 필요하면 표로 그린다.

**표준 반례 세트** (매번 전부 시도)

| 범주 | 입력 예 |
|---|---|
| 빈 값 | `[]`, `""`, `null`, `{}` |
| 단일 원소 | `[x]` |
| 전부 동일 | `[2,2,2,2]` |
| 경계값 | 0, 1, -1, `Integer.MAX_VALUE`, `Number.MAX_SAFE_INTEGER` |
| 정렬 안 된 / 역순 | `[3,1,2]`, `[5,4,3,2,1]` |
| 중복 키 | 같은 id 두 번 |
| 큰 입력 | n = 1e5 (성능 + 스택 깊이) |
| 유니코드·공백 | `" a "`, 이모지, 결합 문자 |

**부동소수점**: `0.1 + 0.2 !== 0.3`. 금액은 정수(cent) 또는 `BigDecimal`.
**정수 오버플로**: Java `int` 합계는 `long`으로. JS는 `2^53` 초과 시 `BigInt`.

## Gate 3 — 복잡도 검증

- 중첩 루프가 숨어있지 않은가 (루프 안의 `includes` / `indexOf` / `contains`는 O(n))
- 루프 안에서 배열·문자열을 새로 만들지 않는가 (`str += x`, `[...arr, x]`)
- 재귀 깊이가 입력 크기에 비례하지 않는가 (스택 오버플로)
- 요구된 복잡도를 실제로 만족하는가 — 말이 아니라 라인 근거로

## Gate 4 — 설명 가능성 검증 (머지 게이트)

아래 4개에 막힘없이 답할 수 있어야 머지한다.

1. 이 코드가 하는 일을 3문장으로
2. 핵심 자료구조를 왜 그것으로 골랐는지
3. 이 코드가 틀릴 수 있는 입력 하나
4. 시간이 더 있다면 무엇을 개선할지

하나라도 못 답하면 코드를 다시 읽거나, 내가 이해하는 더 단순한 구현으로 바꾼다.
6개월 뒤 이 코드를 고칠 사람은 나다.
**이해되는 O(n log n)이 이해 안 되는 O(n)보다 낫다.**

## 게이트 통과 로그

각 사이클마다 한 줄씩 남긴다.

```
[cycle 3] maxWindow 구현 → Gate0 통과(deps 확인) / Gate2에서 빈 배열 실패 발견 → 가드 추가 → 재통과
```

이 로그는 PR 설명에 그대로 옮겨 쓸 수 있고, 리뷰어가 어디를 집중해서 볼지 알려준다.
