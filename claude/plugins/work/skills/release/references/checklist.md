# 릴리즈 체크리스트

## 릴리즈 전

- [ ] `main` CI green, 빌드 성공
- [ ] 지난 태그 이후 커밋 타입 훑어 버전 상승 단계 결정 (fix→patch, feat→minor, !→major)
- [ ] 스키마 마이그레이션 포함 여부 + 배포 순서 확인 (`migrate`)
- [ ] 배포 순서 의존 티켓 확인 (다른 PR이 먼저 나가야 하나)
- [ ] 대상 환경에 시크릿·설정·피처 플래그 준비됨
- [ ] changelog 초안 — 사용자 관점, 내부 잡무 제외
- [ ] 롤백 방법 확정 (코드 / 스키마 / 피처 플래그)
- [ ] 롤백 트리거 기준 (에러율·레이턴시 임계치)

## 배포 중

- [ ] 태그 생성·push (`v1.3.0`)
- [ ] 배포 순서 준수 (마이그레이션 ↔ 코드)
- [ ] staging 스모크 통과 후 prod 승격
- [ ] (가능하면) 카나리/점진 배포

## 배포 후

- [ ] 헬스체크·핵심 엔드포인트 200
- [ ] 스모크: 최중요 플로우 실제 실행 (prod 대상 e2e 스모크)
- [ ] 에러율·레이턴시 대시보드 배포 직후 관찰
- [ ] 마이그레이션 데이터 샘플 확인
- [ ] Jira/이슈에 릴리즈 반영, 관련자 공지

## changelog 도구

| 도구 | 스택 | 특징 |
|---|---|---|
| `git-cliff` | 범용(Rust) | Conventional Commits → changelog, 설정 유연 |
| `changesets` | JS 모노레포 | PR에 changeset 파일, 패키지별 버전 |
| `standard-version` | JS | 버전 bump + changelog + 태그 한 번에 (유지보수 종료 주의) |
| `release-please` | 범용(Google) | 릴리즈 PR 자동 생성, GitHub 통합 |
| Maven/Gradle release plugin | Java | 버전 관리 + 태그 |

## 롤백 시나리오

| 상황 | 대응 |
|---|---|
| 코드만 문제 (스키마 무관) | 직전 태그 재배포 |
| 스키마 추가됨 + 코드 문제 | 코드만 롤백 (추가 컬럼은 구 코드가 무시 → 안전, expand 단계라서) |
| 스키마 삭제됨 + 코드 문제 | 위험 — 구 코드가 없는 컬럼 참조. 그래서 contract(삭제)는 안정 확인 후 별도 배포 |
| 데이터 삭제/변환됨 | 코드 롤백으로 데이터 복구 불가 → 백업 복원 또는 피처 플래그로 우회 |

→ 롤백 가능성은 `migrate`의 expand-contract를 지켰는지에 달렸다. 각 단계가 독립 배포라야 안전하게 멈춘다.

## 배포 후 이상 징후

- 에러율 급증 → 롤백 트리거 검토
- 특정 엔드포인트만 5xx → 부분 롤백 or 핫픽스
- 레이턴시 상승 → 마이그레이션 락·인덱스 누락 의심
- 조용한 실패(에러 없이 잘못된 데이터) → 스모크·데이터 샘플이 유일한 방어
