# UI Fidelity

디자인을 코드로 옮길 때의 실패는 하나로 수렴한다 — **디자인 드리프트.**
시안은 멀쩡한데 구현하는 동안 "이 정도면 비슷하다"가 조금씩 쌓여서, 다 만들고 보면
시안과 다른 화면이 나온다. 각 단계에서는 아무도 크게 틀리지 않았는데 결과가 틀린다.

드리프트는 **짐작으로 코딩할 때** 생긴다. 그래서 순서를 고정한다:

값 추출 → 디자인 시스템 매핑 → 구현 → 렌더 대조

`browser`와 축이 다르다. `browser`는 **동작하나**를 보고, 이 스킬은 **시안대로 나왔나**를 본다.
둘 다 필요하면 `browser`가 먼저다 — 안 뜨는 화면은 대조할 것도 없다.

## 1단계: 값으로 추출한다 — 형용사 금지

"깔끔한 간격", "큰 제목"으로 적으면 구현할 때 다시 짐작하게 된다. **숫자와 문자열로 적는다.**

피그마가 있으면 MCP로 값을 직접 읽는다. 이미지를 눈으로 재는 것보다 정확하고 빠르다.

```
get_figma_data          fileKey + nodeId → 레이아웃·타이포·색·컴포넌트 트리
download_figma_images   래스터·SVG 에셋
```

**노드 ID는 사용자에게 받는다.** 피그마 URL의 `node-id` 파라미터다. 추측해서 다른 프레임을 읽으면
전혀 다른 화면을 구현하게 된다.

이미지·스크린샷뿐이면 화면을 읽고 아래 표를 채운다.
**읽을 수 없는 값은 "읽을 수 없음"이라고 쓴다.** 빈칸을 그럴듯한 값으로 메우는 순간 드리프트가 시작된다.

| 축 | 뽑을 것 |
|---|---|
| 텍스트 | 보이는 문구 전부 — 제목·본문·버튼 라벨·플레이스홀더·에러 문구. 오타까지 그대로 |
| 타이포 | 크기 관계(제목이 본문의 몇 배), weight, 줄 수, 줄바꿈 위치, 정렬 |
| 간격 | 섹션 상하 여백, 요소 사이 간격, 좌우 거터, 카드 내부 패딩 |
| 색 | 배경·표면·텍스트 위계(주/보조/비활성)·보더·강조색·상태색 |
| 컴포넌트 | 버튼 높이·패딩·radius·fill/outline·아이콘 유무, 인풋 높이, 카드 구조 |
| 구조 | 그리드 열 수, 정렬 기준, 반복 단위, 섹션 순서 |
| 상태 | hover·focus·disabled·로딩·빈 상태·에러 |

**상태는 시안에 없는 경우가 대부분이다.** 없으면 "없음"이라고 적고 목록으로 남긴다.
구현에는 반드시 필요하므로, 여기서 적어두지 않으면 구현 중에 즉흥적으로 지어내게 된다.

## 2단계: 디자인 시스템에 매핑한다 — 임의값을 새로 만들지 않는다

**추출한 값을 그대로 하드코딩하지 않는다.** 시안의 `#3B82F6`을 그대로 박으면 테마가 바뀔 때
이 화면만 안 바뀐다. 저장소의 토큰·컴포넌트로 먼저 옮긴다.

```bash
# 무엇을 쓰고 있는지부터 확인한다 — 없는 토큰을 지어내지 않는다
ls src/components/ui src/styles 2>/dev/null
sed -n '1,80p' tailwind.config.* 2>/dev/null      # theme.extend 의 spacing·color·fontSize
git ls-files | sed -n 's|.*/design-system.*|&|p' | head -20
```

매핑 규칙, 이 순서로 적용한다.

1. **기존 컴포넌트가 있으면 그것을 쓴다.** 시안과 2~3px 다르다고 새로 만들지 않는다
2. 토큰이 있으면 토큰으로. `p-6`이 24px이면 `p-[24px]`가 아니라 `p-6`
3. 정말 없는 값이면 임의값을 쓰되 **왜 토큰을 못 썼는지 주석 한 줄**을 남긴다

| 시안 값이 가장 가까운 토큰과 어긋날 때 | 판단 |
|---|---|
| 1~2px | 토큰으로 간다. 시안 렌더링 오차 범위다 |
| 3~7px | 토큰으로 가되 보고 목록에 올린다 |
| 8px 이상 | **멈추고 묻는다.** 의도한 예외인지 시안 실수인지 사람이 정한다 |

## 3단계: 구현 — 시안에 없는 것을 더하지 않는다

구현 중에 떠오르는 "이러면 더 좋을 것 같은데"가 드리프트의 다른 이름이다. 자주 나오는 것:

- 시안에 없는 카드·보더·배경 패널로 요소를 감싸기 (**박스 중첩** — 가장 흔하다)
- 시안에 없는 배지·칩·아이콘·구분선 추가
- 시안에 없는 애니메이션·트랜지션
- 라벨 문구를 "더 자연스럽게" 다시 쓰기 — **카피는 디자인의 일부다.** 길이가 레이아웃을 결정한다
- 여백을 "화면에 맞춰" 줄이기 — 시안의 여백은 대개 의도다

더 좋은 안이 있으면 **구현하지 말고 말한다.** 디자이너가 판단할 몫이고, 말하는 데 30초면 된다.

반대로 **시안에 있는데 구현에서 빠지는 것**도 같은 무게로 본다: 빈 상태, 긴 텍스트 줄바꿈,
비활성 버튼, 로딩 스켈레톤. 1단계에서 만든 상태 목록을 여기서 다시 꺼낸다.

## 4단계: 렌더 대조 — 주장하지 말고 측정한다

**"시안대로 구현했습니다"는 검증이 아니다.** 브라우저에 띄워 실제 값을 뽑아 1단계 표와 대조한다.
스크린샷을 눈으로 겹쳐 보는 것으로는 8px 어긋남이 안 잡힌다 — 그건 QA에서 잡힌다.

```javascript
// ui-check.mjs — 시안 대조용. browser 스킬의 check.mjs 와 목적이 다르다(동작 아니라 값)
import { chromium } from 'playwright';

const [url] = process.argv.slice(2);
const browser = await chromium.launch();
// 시안 기준 폭으로 고정한다. 기본 뷰포트(1280×720)에서 재면 전부 다른 값이 나온다
const page = await browser.newPage({ viewport: { width: 1440, height: 900 } });
await page.goto(url, { waitUntil: 'networkidle' });

const targets = [['heading', '사용자 등록'], ['button', '가입']];

for (const [role, name] of targets) {
  const v = await page.getByRole(role, { name }).evaluate(n => {
    const s = getComputedStyle(n), r = n.getBoundingClientRect();
    return {
      size: `${Math.round(r.width)}×${Math.round(r.height)}`,
      font: `${s.fontSize}/${s.lineHeight} ${s.fontWeight}`,
      pad: s.padding, radius: s.borderRadius, bg: s.backgroundColor, color: s.color,
    };
  });
  console.log(role, name, v);
}

// 간격은 두 요소의 경계로 잰다 — margin 값을 읽는 것보다 정확하다(마진 상쇄가 있다)
console.log('제목→본문 간격', await page.evaluate(() => {
  const a = document.querySelector('h1').getBoundingClientRect();
  const b = document.querySelector('h1 + p').getBoundingClientRect();
  return Math.round(b.top - a.bottom);
}));

await page.screenshot({ path: 'ui-1440.png', fullPage: true });
await browser.close();
```

폭을 하나만 확인하지 않는다. **최소 두 폭**을 본다.

```bash
node ui-check.mjs http://localhost:3000/signup     # 시안 기준폭 (보통 1440)
# 뷰포트를 1280×800 으로 바꿔 한 번 더 — 작은 노트북에서 첫 화면이 잘리지 않는가
# 그리고 375×812 — 모바일 시안이 있으면 그것과, 없으면 깨지지 않는지만
```

측정값이 1단계 표와 어긋나면 **코드를 고친다.** 표를 고치지 않는다.
표가 틀렸다고 판단되면 그건 1단계 추출 실패이므로 다시 추출한다.

### 보고 형식

```
## 디자인 대조 (1440×900)
- 소스: 피그마 <URL> node-id=12:345 (또는 시안 이미지 N장)
- 일치: 타이포 위계 ✓ / 색 토큰 ✓ / 버튼 규격 ✓ / 그리드 ✓
- 어긋남: 섹션 상하 여백 시안 80px → 구현 64px (`py-16`, 가장 가까운 토큰 `py-20`=80px 로 교체함)
- 매핑 예외: 카드 radius 14px — 토큰에 12/16 뿐. 12px 사용, 확인 필요
- 시안에 없어 지어낸 것: 없음 (또는 <목록>)
- 미구현 상태: 빈 목록·에러 — 시안 없음, 디자이너 확인 요청
- 확인한 폭: 1440 / 1280 / 375
```

**"괜찮아 보입니다"로 끝내지 않는다.** 무엇을 쟀고 무엇을 못 쟀는지 쓴다.

## 모호할 때 해소 순서

시안이 답을 주지 않을 때 이 순서로 내려간다. 위에서 답이 나오면 멈춘다.

1. 같은 시안의 다른 요소에서 같은 패턴을 찾는다 (그 화면의 내부 규칙)
2. 저장소의 기존 화면에서 같은 패턴을 찾는다 (제품의 관례)
3. 디자인 시스템의 기본값을 쓴다
4. **그래도 없으면 묻는다.** 지어내고 나중에 고치는 비용이 지금 묻는 비용보다 크다

3번까지 내려왔으면 **무엇을 어떻게 채웠는지 보고에 적는다.** 조용히 채우지 않는다.

## 하지 말 것

| 안티패턴 | 실제 비용 |
|---|---|
| 스크린샷만 겹쳐 보고 "비슷하다" | 8px 어긋남은 눈에 안 잡히고 QA에서 잡힌다 |
| 시안 색·크기를 그대로 하드코딩 | 테마·다크모드에서 이 화면만 안 바뀐다 |
| 2~3px 다르다고 컴포넌트 새로 만들기 | 디자인 시스템이 두 벌이 된다 |
| 읽을 수 없는 값을 그럴듯하게 채우기 | 드리프트의 시작점 |
| 시안에 없는 상태를 즉흥 구현 | 디자이너가 모르는 화면이 프로덕션에 나간다 |
| 라벨 문구를 임의로 다듬기 | 카피 길이가 레이아웃을 바꾼다 |
| 기본 뷰포트에서 대조 | 시안 기준폭이 아니라 측정값이 전부 틀린다 |
| 반응형을 나중 일로 미루기 | 폭 하나만 맞춘 레이아웃은 대개 다시 짠다 |
| 피그마 노드 ID 추측 | 다른 프레임을 구현한다 |

## work 사슬 연결

- `plan`의 슬라이스에 화면 작업이 있으면 이 스킬로 그 슬라이스를 끝낸다.
- 동작 확인은 `browser`, 회귀 자산으로 남길지는 `e2e`가 정한다. 이 스킬의 `ui-check.mjs`는 버리는 것이다.
- 매핑 예외(8px 이상)와 시안에 없던 상태는 `pr` 본문의 「리뷰 포인트」로 올린다.
- 시안 자체가 틀렸다고 판단되면 고치지 말고 `ticket`으로 남긴다.
