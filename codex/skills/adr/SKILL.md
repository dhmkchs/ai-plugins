# ADR — Architecture Decision Record

**설계 판단은 코드에 남지 않는다.** 6개월 뒤 "왜 이 구조?"에 답할 수 있는 건 그때 적어둔 근거뿐이다.
ADR은 결정 자체가 아니라 **대안과 trade-off와 결과**를 박제해서, 나중에 뒤집을지 판단할 근거를 남긴다.

## 언제 쓰나 — 아무 결정에나 쓰지 않는다

ADR은 **되돌리기 비싼 결정**에만 쓴다. 다음 중 둘 이상이면 쓴다.

- 나중에 바꾸려면 여러 파일·팀·배포를 건드려야 한다 (모듈 경계, 저장소 선택, 인증 방식)
- 합리적 대안이 둘 이상 있었고, 선택이 자명하지 않았다
- 팀원이 나중에 "왜 이렇게 했지"를 물을 것이다
- 그 결정이 다른 결정을 제약한다 (프레임워크·프로토콜·데이터 모델)

변수 이름, 포맷팅, 자명한 선택은 ADR 대상이 아니다. **ADR이 흔해지면 아무도 안 읽는다.**

## 1. 컨텍스트 — 무엇을 왜 정해야 하나

결정 자체로 뛰지 않는다. 먼저 압력을 적는다.

- 어떤 문제·요구가 이 결정을 강제하나
- 제약: 성능·마감·팀 역량·기존 스택·규정
- 결정하지 않으면 무엇이 막히나

컨텍스트는 **사실만.** "우리가 X를 원한다"가 아니라 "요청당 p99 200ms를 넘으면 안 된다" 처럼 검증 가능하게.

## 2. 대안 — 최소 둘, 각각 정직하게

하나만 적힌 ADR은 사후 정당화다. **채택하지 않은 안도 그 장점을 정직하게 적는다.**

```
### 대안 A — 모듈형 모놀리스
- 장점: 단일 배포, 트랜잭션 경계 단순, 팀 규모에 맞음
- 단점: 모듈 경계가 코드 규율에만 의존, 언젠가 분리 비용

### 대안 B — 서비스 분리
- 장점: 독립 배포·스케일, 경계가 네트워크로 강제됨
- 단점: 분산 트랜잭션, 운영 복잡도, 현재 팀 규모엔 과함
```

대안이 하나밖에 안 떠오르면 아직 문제를 충분히 이해 못 한 것이다. "아무것도 안 한다(현상 유지)"도 항상 유효한 대안이다.

## 3. 결정 — 무엇을, 왜 이 맥락에서

- **채택**: 어느 안
- **근거**: 이 맥락의 어떤 제약이 이 안을 골랐나 (§1 컨텍스트와 연결)
- **왜 일반 원칙이 아니라 이 맥락인가**: 같은 결정이 다른 프로젝트에선 달라질 수 있음을 인정한다

"B가 더 좋아서"가 아니라 "**현재 팀 3명·단일 DB·6주 마감**이라는 제약에서 B의 단순성이 A의 확장성보다 값지다"로 쓴다.

## 4. 결과 — 좋은 것과 나쁜 것 다

결정은 대가를 동반한다. 그걸 미리 적어두면 나중에 "이럴 줄 몰랐다"가 안 된다.

- **긍정적 결과**: 이 결정이 열어주는 것
- **부정적 결과 / 감수하는 비용**: 포기한 것, 나중에 물어야 할 빚
- **후속 필요**: 이 결정이 강제하는 다음 작업 (있으면)

## 5. 상태 관리 — ADR은 지우지 않는다

ADR은 **불변 기록**이다. 결정이 바뀌면 옛 ADR을 고치지 않고, 새 ADR을 쓰고 옛것을 `Superseded`로 표시한다.

| 상태 | 의미 |
|---|---|
| `Proposed` | 논의 중, 아직 안 정해짐 |
| `Accepted` | 채택됨, 현재 유효 |
| `Superseded by ADR-NNNN` | 후속 ADR로 대체됨 (옛 ADR 본문은 그대로 둔다) |
| `Deprecated` | 더 이상 유효하지 않지만 대체안 없음 |

옛 결정을 지우면 "왜 그때 그렇게 했나"가 사라져, 같은 실수를 반복한다.

## work 사슬 연결

- `plan`의 `## 설계 판단` 절에서 되돌리기 비싼 판단이 나오면 → 여기서 ADR로 승격한다. 플랜은 이번 작업용, ADR은 프로젝트 영속 기록이다.
- ADR을 썼으면 `pr` 본문 `## 설계 판단`에서 그 ADR을 링크한다 — 리뷰어가 근거를 따라갈 수 있게.

## 하지 말 것

| 안티패턴 | 실제 비용 |
|---|---|
| 대안 하나만 적기 | 사후 정당화가 됨, 판단을 뒤집을 근거가 없음 |
| 채택 안 한 안의 단점만 적기 | 정직하지 않음, 나중에 재검토 불가 |
| 결과(비용) 생략 | "이럴 줄 몰랐다"가 반복됨 |
| 옛 ADR을 고쳐서 갱신 | 결정의 역사가 사라짐 — 새 ADR로 supersede |
| 사소한 결정까지 ADR | 노이즈로 아무도 안 읽게 됨 |
| "베스트 프랙티스라서" | 이 맥락의 제약과 연결 안 되면 근거가 아님 |
