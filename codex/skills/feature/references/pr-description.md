# PR 설명 템플릿

목표는 **리뷰어가 물어볼 질문을 미리 답하는 것**이다.
PR 설명에 쓰는 10분이 리뷰 대기 하루를 아낀다.

---

```markdown
## 무엇을 / 왜

사용자 등록 API에 중복 이메일 검증을 추가했습니다.
기존에는 중복 이메일로 계정이 두 개 생성되어 로그인 시 어느 쪽으로 붙을지 비결정적이었습니다.
(#1234)

## 요구사항 충족

| # | 요구사항 | 상태 | 확인 |
|---|---|---|---|
| 1 | 중복 이메일 거부 | ☑ | `UserApiTest.중복_이메일이면_409` |
| 2 | 대소문자 무시 비교 | ☑ | `UserApiTest.대소문자가_달라도_중복` |
| 3 | 기존 중복 데이터 정리 | ☐ 후속 | 별도 티켓 #1240 |

## 설계 판단

**검증을 두 곳에 두었습니다**
애플리케이션에서 `existsByEmail`로 먼저 확인하고, DB 유니크 제약을 최종 방어선으로 추가했습니다.
동시 요청에서는 애플리케이션 검사만으로 중복을 막을 수 없어서입니다.
제약 위반 예외는 `@RestControllerAdvice`에서 409로 변환합니다.

**이메일을 소문자로 정규화해 저장합니다**
`A@b.com`과 `a@b.com`을 같은 것으로 취급해야 해서, 조회 시 함수 인덱스를 타지 않도록
저장 시점에 정규화했습니다. 기존 데이터 정리는 후속 티켓으로 분리했습니다.

**도입하지 않은 것**
이메일 검증(verification) 플로우는 이 PR 범위 밖입니다. 요구사항에 없고,
넣으면 상태 관리와 만료 처리가 따라와 리뷰 단위가 너무 커집니다.

## 가정

- 기존 중복 데이터는 이 PR로 정리하지 않습니다. 마이그레이션 전에 유니크 제약을 걸면
  배포가 실패하므로, 제약 추가는 정리 티켓(#1240) 이후로 미뤘습니다. **이 PR은 제약 없이 머지됩니다.**
- 소문자 정규화는 로컬 파트에도 적용했습니다. RFC상 로컬 파트는 대소문자를 구분하지만
  실무상 모든 주요 메일 서비스가 구분하지 않습니다.

## 리뷰 포인트

- `normalizeEmail`을 도메인 객체에 둘지 서비스에 둘지 고민했습니다. 의견 주세요.

## 작성 규칙

**필수**
- 첫 문단에 **무엇을 왜**. 리뷰어가 diff를 보기 전에 맥락을 갖게 한다
- 이슈 번호 링크
- 요구사항 충족 표 — 무엇이 남았는지 명시
- 설계 판단마다 **근거** ("~해서 ~로 했습니다")
- 리뷰 포인트 — 어디를 집중해서 봐야 하는지 지목
- 확신 없는 부분은 확신 없다고 쓰고 의견을 구한다

**하지 말 것**
- 코드를 설명하는 설명 (diff를 읽으면 안다). 설명할 건 **왜**다
- "간단한 수정입니다" — 리뷰어가 판단할 일이다
- 구현 코드를 본문에 붙여넣기
- 미구현 숨기기 — 발견되고, 신뢰 비용이 코드 비용보다 크다
- 배포 시 주의사항 누락 (마이그레이션 순서, 설정 추가, 롤백 불가 여부)

**배포에 순서 의존성이 있으면 반드시 맨 위에 쓴다.**
```
⚠️ 배포 순서: 이 PR을 먼저 배포한 뒤 #1240을 배포해야 합니다. 반대로 하면 제약 위반으로 배포가 실패합니다.
```

## PR 크기

리뷰 가능한 크기는 **400줄 이내**다. 그 이상이면 리뷰 품질이 급격히 떨어진다 (읽는 척하고 승인한다).

크면 쪼갠다:
- 리팩터링과 기능 변경을 분리 (거의 항상 가능하고, 거의 항상 옳다)
- 스키마 변경과 코드 변경을 분리
- 인터페이스 추가와 사용처 변경을 분리

쪼갤 수 없으면 커밋 단위를 논리적으로 정리해서 **커밋별로 읽을 수 있게** 만들고, 그 사실을 설명에 적는다.
```
커밋 단위로 보시면 읽기 쉽습니다: 1) 도메인 모델 추가 2) 서비스 로직 3) 컨트롤러 연결 4) 테스트
```

## 머지 전 최종 확인

```bash
# 최신 base와 충돌 없는지
git fetch origin && git rebase origin/main

# 깨끗한 상태에서 전체 검증
npm ci && npm test && npm run build
./gradlew clean build

# 커밋되면 안 되는 것
git diff origin/main --name-only
git ls-files | grep -E "\.env$|\.pem$|credentials|\.DS_Store|/build/|/target/"
```
